ORIGINAL SUBMISSION (2018)
================================================================================

Project Option: Option 2 — Ticketmaster + iTunes APIs

The project searched for recent concerts by US postal code using the Ticketmaster
Discovery API, retrieved the top 10 songs per performing artist via the iTunes
Search API, and wrote results to a CSV file.

Key components:
  - CLI input loop (postal code prompt)
  - Two classes: TicketmasterEvent, ITunesMedia
  - File-based JSON cache (cache_cache_cache.json)
  - Output: event_media.CSV

Entry point: SI506F18_final_project.py
Dependencies: requests, json, csv, sys

================================================================================
MODERNIZATION (2026)
================================================================================

The project has been rewritten as an async FastAPI web service while keeping
the same core idea: find nearby concerts and surface top songs for each artist.

--- Architecture ---

  app/
    main.py           — FastAPI app, /api/search endpoint, /api/cache/clear
    models.py         — Pydantic models: Concert, Track, ArtistTracks, SearchResult
    cache.py          — In-memory async cache (_store dict, TTL-based)
    config.py         — Settings via pydantic-settings (.env)
    services/
      ticketmaster.py — fetch_concerts(): geocode ZIP → Ticketmaster API
      itunes.py       — fetch_tracks_for_many(): iTunes Search API
    static/
      index.html      — Single-page frontend (Tailwind CSS, vanilla JS)

  tests/
    test_ticketmaster.py  — 5 unit tests for fetch_concerts
    test_search_api.py    — 8 unit tests for /api/search

--- What Changed ---

  From CLI → async FastAPI web service
  From file-based JSON cache → in-memory TTL cache (app/cache.py)
  From postalCode param → lat/long via Nominatim geocoding (OpenStreetMap)
  From segmentName filter → segmentId "KZFzniwnSyZfZ7v7n1" for reliable Music filter
  From CSV output → JSON API responses rendered in browser
  Added: time range filter (This Week / This Month / Next 3 Months presets)
  Added: calendar-valid date validation, ISO 8601 conversion
  Added: context-aware empty-state messaging
  Added: /api/cache/clear endpoint

--- API Endpoints ---

  GET  /api/search        Search concerts + artist tracks
       postal_code        5-digit US ZIP (required)
       radius             Search radius in miles, default 50
       concerts_limit     Max concerts returned, default 3
       tracks_limit       Max tracks per artist, default 10
       start_date         YYYY-MM-DD, defaults to today
       end_date           YYYY-MM-DD, optional

  POST /api/cache/clear   Flush in-memory cache, returns {"cleared": N}
  GET  /api/health        Health check

--- Data Sources ---

  Ticketmaster Discovery API v2
  https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/
  API key required — set TICKETMASTER_API_KEY in .env

  iTunes Search API
  https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/
  No API key required

  Nominatim (OpenStreetMap) — ZIP code to lat/long geocoding
  https://nominatim.org/release-docs/latest/api/Search/
  No API key required
